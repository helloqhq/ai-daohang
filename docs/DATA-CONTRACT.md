# 网站 JSON 数据契约

状态：已实现 schemas/event.schema.json、scripts/collector/validation.py 和 public/data/ 快照。获取方式已统一 RSS/Atom。

## 文件与公开边界

以下是实际项目相对路径。以 `public/` 为发布输入之一，只发布网站所需文件，不把整个仓库工作目录直接作为发布产物。

| 文件 | 用途 |
| --- | --- |
| `config/entities.json` | 关注对象、别名与关联关系配置 |
| `config/sources.json` | 信息源、负责人账号、核实依据和启用状态配置 |
| `public/data/catalog.json` | 网站展示与筛选需要的对象、负责人和来源元数据 |
| `public/data/index.json` | 数据版本、生成时间、按月历史文件索引、事件位置与统计 |
| `public/data/events/YYYY-MM.json` | 相应月份的事件内容 |
| `public/data/coverage.json` | 经过整理的来源采集覆盖状态 |
| `.collector/state.json` | 各来源成功区间、未完成区间和去重状态，不进入发布目录 |
| `.collector/cache/` | 有保留期限的RSS/Atom 原始 XML 缓存，不进入发布目录 |
| `.collector/pending.jsonl` | 已发现／已取回但尚未完成语义加工的候选材料，不进入发布目录 |
| `.collector/runs/` | 必要的本地运行结果与修订核查记录，不进入发布目录 |

公开仓库中同样不提交内部采集状态及运行记录。公开配置只包含公开入口和身份依据，不包含账号凭据。

浏览器根据日期筛选加载所需月份文件，再在选定范围内进行关键词过滤。长期保留历史，不要求默认首页一次加载全部历史。

## 共同约定

公开文件带 `schema_version: "1.1"`（双语必填）与同一 `snapshot_id`，使页面能够识别数据契约和快照是否一致。`index.json` 的 `generated_at` 表示数据快照生成时间，不表示所有来源成功时间或站点发布时刻。

对象、来源和事件使用稳定且唯一的标识。名称或来源地址变化不更换对象标识；中文摘要修改不更换事件标识。记录按标识引用，不能用展示名称作为关联键。

实际抓取、生成和更正时间采用带时区的 ISO 8601 时间；页面按 Asia/Shanghai 展示。原文只有日期时保存日期与精度，不编造时分秒。原始时间无法核实时明确记录未知，并留待核查是否符合采集时间窗。

## 关注对象与信息源

关注对象记录：`id`、`name`、`aliases`、`category`（模型或 Agent）、`kind`（厂商、模型品牌、应用或运行工具）、`enabled`，需要时附所属组织及模型系列关系。

负责人记录：`id`、`name`、`entity_ids`、身份核实链接和已经核实的账号入口。官网能核实身份不等于所有同名账号都属于该人。

信息源记录：`id`、`name`、`entity_ids`、可选 `person_id`、`url`、来源格式、`platform`、可选账号／频道标识、`adapter`、`capabilities`、`enabled`、核实状态及依据。配置状态与实际采集成功／失败分开记录。

`platform` 支持官网、GitHub、YouTube、TikTok、X、微信公众号及后续扩展；`adapter` 统一为 rss；`feed_url` 是 RSS/Atom 订阅，`url` 是原始来源入口，`rsshub_route` 可配合全局转换服务地址。`capabilities` 分别描述能否发现列表、读取正文或字幕，以及当前访问要求。账号凭据、会话或 access token 不写入公开配置。

展示名称同时维护 `name`（默认中文／品牌名）与 `name_en`；来源订阅说明同时维护 `subscription_note` / `subscription_note_en`，刷新目录时保留这些字段。

官网、官方仓库与指定负责人账号在可信来源类型上区分；搜索页不作为事件最终原始依据。

## 事件字段

| 字段 | 含义与约束 |
| --- | --- |
| `id` | 稳定的事件标识，重复采集与修订后保持不变 |
| `entity_ids` | 一个或多个已登记关注对象 |
| `kind` | `update`、`preview` 或 `opinion` |
| `topics` | 如模型发布、能力、API、价格、可用性、功能、兼容性、关键修复 |
| `title_zh` | 中文标题 |
| `summary_zh` | 忠于原始依据的简短中文摘要 |
| `key_points_zh` | 关键变化列表，不添加原文没有的结论 |
| `importance_reason_zh` | 入选的实际影响或价值 |
| `title_en` / `summary_en` | 必填；与中文同事实的英文标题及摘要 |
| `key_points_en` | 必填；与中文关键点数量、顺序一致 |
| `importance_reason_en` | 必填；入选理由的英文版本 |
| `translation_zh` / `translation_en` | 可选，填写时两份齐全；短公告全文译文，不替代摘要 |
| `published_at` | 已核实的发布时间或原文日期；未知为 `null` |
| `date_precision` | `datetime`、`date` 或 `unknown`，与时间字段一致 |
| `first_collected_at` | 本站首次取得该事件的实际时间 |
| `updated_at` | 本站事件记录最后修改时间，不冒充原文发布时间 |
| `sources` | 至少一个原始依据，包含来源标识、平台原始内容标识、原文链接、可核实原文日期、采集时间、实际材料范围与当前可访问状态 |
| `related_event_ids` | 可选；连接预告与正式发布等关联事件 |
| `corrections` | 可选；更正时间、双语原因 `reason_zh` / `reason_en` 及核实依据 |

同一 JSON 记录内保存两份语言内容，共用 ID、时间和来源，不重复计数。必填文案不能是空白，中英文关键点必须一一对应。实质更正同步修改双语并记录双语理由；仅为旧中文事件补齐英文时保留 ID、首次采集时间，更新 `updated_at`，不添加虚构事实更正。

新内容只有日期时可以按日期展示，日期边界有不确定性时如实标记；完全未知的时间不能仅凭抓取时间认定原文发布于最近 3 天。未能确认时间窗归属的候选内容先进入内部待核查记录。

每条来源依据可附 `material_scope`（`metadata_only`、`partial_text`、`full_text`）、字幕／转写类型和证据定位。视频证据定位记录需要时的开始与结束秒数，文章定位可用段落或原文锚点；不要求平台都支持时间点链接。

`full_text` 指取得相应文字材料全文，不表示完成视频画面理解。仅有标题和简介时，摘要只能描述这些文本明确支持的信息；缺少支持关键结论的材料时保留待核查状态，不能编造视频正文。公开 JSON 不附整段字幕或原始订阅缓存。

内部缓存记录原始内容标识、内容指纹、解析／加工规则版本、材料完整度和有效期。原文或规则变化时重新处理，未变且依据充足的内容复用既有判断与中文结果。

默认排序依据事件发布时间；同一事件新增来源或改写摘要不伪装为新发布。明确更正有可见标记。普通预告与正式发布有独立标识；不能仅凭其涉及同一模型而合并。

按首次登记事件的发布月份确定历史文件位置，后续修订保持位置稳定。索引维护唯一位置和日期范围元数据，时间更正跨月份时检索也能定位到原文件；关联事件在其他月份时按索引读取。

## 公开覆盖状态

每个来源记录配置是否已核实／接入、本次尝试状态、最后尝试时间、最后成功覆盖区间及仍未覆盖的区间概要。内部状态分别保存材料获取进度和内容审阅进度；公开覆盖不能把“已发现／下载”误称为“已全部筛选总结”。

实际尝试状态区分 `success`、`partial`、`failed`、`blocked`、`not_attempted`；未接入来源另外标记配置状态，不把它计入本次成功来源。状态只描述实际查询能力和区间，不保证互联网原始来源完整无遗漏。

成功扫描后没有入选信息也记录成功覆盖。访问成功但时间范围不完整只能标为部分覆盖，不能用零条入选结果证明没有更新。

页面只展示可读的状态、时间和范围概要；不公开原始日志或可能包含敏感信息的错误文本。

## 校验与快照一致性

- 必填字段、枚举、时间精度、URL 和关联引用有效；事件至少有一个原始依据。
- 对象／来源标识存在，事件标识全局唯一，关联事件不产生悬空引用。
- 不因本次对象筛选、部分来源失败或新月份建立而删除既有历史。
- 内容、月份索引、公开覆盖状态及内部进度对应同一次校验通过的数据结果；校验失败不推进成功进度。
- 不设置 token 预算或 token 用量停止条件；因访问失败、材料不足或运行中断而未完成的候选保留待处理状态，已获取材料可缓存，但不能推进相应区间的全部内容审阅进度。
- 在临时位置写入并验证候选结果，完成后整体替换有效快照；失败时恢复或保留上次有效版本。
- 发布只采用一致、通过验证的快照，不将半写入 JSON 上线。客户端发现版本不一致时提示刷新或重新获取，而不把异常解释为没有新闻。
