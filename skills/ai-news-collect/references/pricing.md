# 计费对象、信源与优惠维护

维护模型 API、聊天产品、Token Plan 与 Agent 套餐，包括对象／信源发现、价格、模型权益、免费额度和折扣记录。价格目录是独立核验快照，不受新闻首次回溯 72 小时的限制，也不是实时价格承诺。

## 复用与核验

1. 从项目根运行 `node scripts/maintain-catalog.mjs`，必要时 `--root /项目`。报告汇总已有定价／权益／优惠／基准链接、对象与新闻源映射缺口、过时及到期条目。它不联网，也不代表这些链接已通过核验。
2. 结合变更线索自动发现新的重要模型、聊天产品、套餐与渠道。对象按 [发现规则](discovery.md) 登记，复用 `pricing_provider` / `pricing_product_ids`，同产品不同档位共享动态渠道。`pricing.json` 中价格链接与新闻 RSS 各尽其责；缺新闻渠道时继续核实与接入，不冒充已有完整监测。
3. 优先处理待核验、过时、失败、即将到期及有变更线索的记录，完成调用范围内的计费核验。可读取官方 HTTPS 定价页、公开模型列表、权益文档、活动条款和无需登录的官方公开接口。只读公开信息，不登录购买、不调用收费推理接口，也不自建常驻抓取服务。
4. 对同一 URL 一次读取、按用途复用，核实实际价格、模型版本、地区、上下文、计费单位、资格与期限；相同模型跨平台独立记录。官方资料互相冲突或结算页受限时保留未完成事项，不用搜索摘要、旧缓存或“定价不变”推算新档位。
5. 在完整候选 JSON 上验证后替换目录并运行 `npm run pricing:build`，必要时 `npm test`、`npm run build`。校验失败保留上次有效目录；新闻快照 `refresh` 不能代替价格校验。不提交或部署。

各项 `checked_at` / `models_checked_at` 只在实际读到对应事实后更新；内容变化才更新 `updated_at`。核实了新优惠不能顺便刷新没读到的原价或所有模型权益。优惠基准有自己的日期，旧基准不能通过刷新优惠日期变成新基准。仅日期复核不应制造新的 RSS 内容变更。

## 共享套餐与适用场景

同一购买权益只留一条方案，`use_cases` 可包含 `api`、`chat`、`agent`，多个筛选入口共用该记录。保留现有 `api` / `token-plan` / `agent` 归属；纯聊天产品可用 `category: chat`，仍须有产品、档位和模型权益。不要为 ChatGPT / Codex 或其他共享套餐复制同价档位，也不要把某个 Agent 登录入口停服写成整个聊天订阅停服。不同资格／不同权益确为独立套餐时才分别登记。

## 免费与折扣结构

维护 `public/data/pricing.json` 中方案的 `offers` 数组。完整字段契约见项目 `docs/PRICING.md` 的“免费与折扣契约”。每条优惠有稳定 `id`、`type`、`kind`、`status`、实际适用的 `models`、官方 `source_url`、`checked_at`、双语 `conditions` / `eligibility`、`card_required: yes|no|unknown`。

- 免费 `type: free`，`kind: recurring|signup|trial|limited-time`，另有双语 `quota`，说明额度、刷新／结转规则。支持注册赠送与试用，但只有工具零订阅费、第三方推理仍收费时不生成免费模型优惠。付费套餐的充值奖励须明确付费前提，不能标为无需付费的模型额度。一个工具连接多个模型，只列有免费推理依据的型号，不把支持列表全部标免费。
- 折扣 `type: discount`，`kind: promotion|vs-origin|off-peak|batch|official-discount`。`price` 为优惠适用的价格维度，单位／币种沿用方案。常规表格价格与优惠价分别呈现，不把仅活动人群可用的价格替换成普遍价格。
- 计算折扣需 `reference`：双语 `label`、`comparison`，`currency`、`billing`、`price`、`source_url` 和 `checked_at`。核实同模型、版本、上下文、地区、服务模式和计价口径的可比性；币种、单位和比较维度必须一致。按维度展示节省比例，不平均输入与输出，不跨平台等同 Credits，不按假定汇率换算。缺可靠原价时只展示已核实价格和官方条件，不编造基准或计算比例。

绑卡、地域、账号、邀请、最低消费、超额费用、数据用途等条件只按原文记录；未核实的绑卡要求标 unknown。缺确切额度时如实说明官方未列出，不补造请求数。限时活动用带时区的 `starts_at` / `ends_at`，结束边界为不再生效的时刻；截止某日的北京时间活动可写次日 `00:00:00+08:00`。只有月日没有年份时不能推测具体截止日。发放后 N 天／账期到期的期限写进额度及条件，不伪造所有用户共享的日历截止时间。

没有公布截止日使用 `ends_at: null`，仍需真实近期核验。如果已公布“10月14日”等标签但缺年份，保留 `end_note_zh/en` 的原始期限及不确定性，`ends_at: null`、`status: pending`，不改写成官方从未公布期限。分时优惠明确当地时区、时段、工作日／节假日规则，面板表示条件下可用，不声称此刻所有请求均享优惠。活动结束不代表整个产品停服；仅某优惠到期用优惠自己的 `ends_at`，不要误设方案的 `valid_until`。

## 公开展示与保留

快捷面板默认仅展示已核验有效的优惠，排除未开始、到期、暂停、待核验及超过 30 天未核验的记录。核验日期同时考虑方案价格、模型权益、优惠和比较基准，不能用新优惠掩盖旧价格。未知截止日仍显示“未公布截止日”；用户可另行查看不可用记录。历史条目保留 ID、来源和原因，不静默删除，不把 `null` 当免费。

汇报新增／修改的对象与信源、真实复核范围、价格与权益变更、免费／折扣数量、过期／待核验缺口以及校验结果；不能把本地检查通过说成互联网核验通过。
