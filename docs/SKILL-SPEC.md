# AI 信息采集 skill 设计

状态：已实现，实际入口为 skills/ai-news-collect/SKILL.md 与 scripts/collect.py。2026-10-03 更新为统一 RSS/Atom 采集。

## 目的与边界

用户通过已有 AI agent 按需调用 skill，采集项目配置中关注对象的动态，筛选重要信息并产出网站可读的中文 JSON。

只通过 RSS/Atom 获取信息。官网、GitHub、YouTube、TikTok、X、微信公众号等平台使用原生或转换服务订阅；没有可用订阅时保留待配置，不直接抓原站。RSS 中取得的文字／字幕作为证据，JSON 仍是输出接口。

优先调用既有采集脚本，复用统一 RSS/Atom 读取器。脚本完成稳定的获取与转换，agent 只对新增或实质变化的材料做语义判断与中文加工。尽量节省 token，但不设置 token 预算、总量上限或扩读限额，不因 token 使用量暂停候选处理。详细职责、按需读取和缓存见 [COLLECTION-PIPELINE.md](./COLLECTION-PIPELINE.md)。

skill 只更新并验证项目内数据，不部署网站，不创建或推送远程仓库。首版不添加定时调用。

## 输入

- 项目路径：用于定位配置、已有内容和采集状态。
- 关注对象与来源配置：见 [SOURCE-REGISTRY.md](./SOURCE-REGISTRY.md)。默认处理全部启用来源，允许显式指定对象子集。
- 采集时间窗：首次默认回溯最近 3 天，即调用时刻之前 72 小时；允许用户明确要求其他窗口。
- 本地已有数据、各来源的成功覆盖范围和未完成区间：用于增量、去重和补采。
- 原始材料与加工结果缓存、待处理候选队列；已有成功结果优先复用，因材料不足、访问失败或运行中断而未完成的候选保留待处理状态。

只采集对象子集时，不删除其他对象历史，不把未查询的来源标记为本次成功。

## 内容规则

采用 PLAN.md 已确认的筛选和中文呈现规则。每条入选信息应有原始依据、关注对象和具体入选理由，不只给出缺乏解释的“重要性分数”。

中文标题、摘要和关键变化为默认输出。短公告可附完整译文，长文章只总结；译文与摘要分开指称。明确标记预告和观点，不把来源自身的性能宣称写成独立核实结论。

## 一次调用的流程

1. 读取配置、数据契约和已有状态，确定实际查询的来源与时间范围。
2. 调用统一 RSS 脚本获取订阅变更清单和订阅提供的文字／字幕，记录原始链接、可核实的发布时间、抓取时间和材料完整度。搜索结果只用来发现原文；脚本默认返回简短索引与本地材料路径。
3. 脚本按原始内容标识与指纹确定性去重，并复用未失效的加工结果；agent 对剩余候选按需读取材料，识别同一发布的多条来源。预告与正式发布分开关联，不能只按标题相似度或整页 URL 合并。
4. agent 按实际影响筛选，生成中文内容、入选理由和来源引用。不能仅凭关键词规则丢弃尚未审阅的高价值候选；没有读到字幕不能把简介改写成完整视频摘要。
5. 脚本复核近期已有材料，仅将实际变更、新增证据或缓存失效的事件交给 agent 处理，保留必要的修订记录，不要求重新阅读全部近期事件。
6. 在临时位置生成候选 JSON，验证结构、字段、引用、时间、去重及历史保留。
7. 校验通过后更新有效数据快照及相匹配的采集状态；任何校验失败均保留上次有效数据和进度。
8. 汇报本次新增、合并、更正、失败来源和未覆盖区间。发布网站由独立流程处理。

## 增量与补采

按来源保存成功覆盖范围，不以某次运行的总体完成时间代替所有来源的进度。访问失败、结果不完整或时间区间未覆盖时，只记录实际完成部分和缺口。

后续补采从失败来源的未完成区间继续，不能直接重设为最近 3 天。正常增量采用小幅重叠范围，并重新核查近期已入选记录以发现延迟发布和更正。

成功扫描但没有重要信息是有效结果，可以推进该来源进度。搜索只找到零散原文不能据此宣称整个时间窗已覆盖；不得编造发布时间来使内容符合窗口。

无法访问时优先尝试配置内该对象的其他官方来源；仍无法访问则记录缺口，在本次调用后停止该来源的无限重试，等待后续调用补采。

## 输出

网站 JSON、公开覆盖状态与内部状态按 [DATA-CONTRACT.md](./DATA-CONTRACT.md)组织。

对用户汇报：实际查询区间和对象范围、新增与更正数量、没有重要更新的已检查来源、失败或受限来源、尚未接入来源、未覆盖区间、材料不完整和尚未完成加工的候选、缓存复用情况、输入材料规模、校验结果，以及数据文件路径。只有运行环境提供可靠计量时才报告实际 token 用量；估算值明确标注。

不能把“部分成功”描述为完整覆盖。候选入口未验证、负责人账号未核实或站点无法读取时，保留明确状态，不生成虚构新闻。

## 实施时的 skill 结构

已实现名称为 `ai-news-collect`。主 SKILL.md 只保留目的、输入输出、关键行为和引用入口；来源名单在项目配置中维护，数据约束与内容规则在必要引用中维护，避免为每次扩展重写 skill。

skill 源文件随项目版本维护；安装到用户所用 agent 的发现目录已按本机 agent 的发现目录安装。采集、解析、缓存和校验脚本作为核心交付，优先扩展现有模块而非每次临时生成脚本；脚本的详细实现不要求 agent 每次读入上下文。

## 行为验证

覆盖首次 3 天、重复调用、限定对象采集、失败后补采、成功但无入选信息、多来源归并、预告关联正式发布、明确更正、JSON 校验失败及历史保留。新增验证：同平台新账号复用脚本、未变内容不重复加工、内容或规则变化后缓存失效、长字幕按段读取、仅元数据时如实降级、分批处理完整且不因 token 用量暂停、运行中断后可恢复未完成候选。可以用隔离的固定输入验证这些行为，不把实际来源偶发访问失败当作算法正确性的证明。
