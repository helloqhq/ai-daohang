# AI 信息聚合静态网站计划

状态：首版网站、采集 skill、统一 RSS 读取器、JSON 校验及独立 Pages 发布流程已实现；正式访问域名改为 go2-ai.com，GitHub Pages 绑定完成后等待 DNS 与 HTTPS 生效。2026-10-03 按用户最新要求改为统一 RSS/Atom 获取信息；未接通订阅明确记录缺口。

## 目标与首版范围

服务用户本人及 AI 开发者，帮助快速了解值得跟进的新模型、新能力和 Agent 工具变化。汇聚官方动态和明确指定的负责人自媒体，筛选重要信息后提供中文阅读内容和原文入口。来源覆盖官网、博客、项目发布记录，以及 YouTube、TikTok、X、微信公众号等媒体渠道。

网站纯静态、公开访问，使用免费 GitHub Pages、公开仓库及独立域名 go2-ai.com。采集由用户已有 AI agent 按需调用专用 skill 完成，不需要常驻后端或额外收费采集 API。已有 agent 的使用成本不属于静态托管成本。

首版不包含账号、订阅、个性化推荐或定时调用。用户指定的 Agent 运行工具纳入名单，不主动扩大到其他开发框架。

## 数据生产与网站发布

```text
用户发起 AI agent
  → 调用采集 skill
  → 读取关注对象、来源配置与已有数据
  → 复用统一 RSS/Atom 读取脚本：获取订阅变更、清理文字、标准化、缓存与确定性去重
  → 仅把新增或实质变化的候选材料交给 AI agent
  → AI 判断重要性、归并事件并生成中文内容
  → 验证并更新项目内 JSON
  → 输出采集结果及失败来源

独立网站发布
  → 选择通过验证的数据快照与静态页面
  → 部署到 GitHub Pages
  → 浏览器读取本站 JSON
```

JSON 是本站数据接口。信息获取统一使用 RSS/Atom：官方原生订阅优先，无原生订阅的官网和媒体账号通过 RSS 转换服务接入。采集流程不直接抓官网、GitHub API 或社交页面；网站不直接读取上游或调用 AI 模型。统一订阅决策见 ADR 0003。

采集 skill 不创建远程仓库、不推送代码、不部署网站。实施阶段配置独立发布流程，选定数据与静态页面作为同一个发布版本上线。

## 脚本复用与 token 节省

已确认新增要求：采集 skill 优先调用可复用脚本，避免每轮让 agent 重新生成采集代码、逐页阅读重复内容或把原始网页全部放入上下文。

脚本负责来源枚举、分页、时间过滤、正文提取、字幕分段、缓存、内容指纹、确定性去重、状态维护与 JSON 校验。AI agent 负责重要性判断、跨来源事件归并、事实表达边界、中文摘要和必要翻译。

所有平台复用同一个 RSS/Atom 读取器，关注名单、账号和订阅地址放配置中；新增兼容订阅不复制脚本。工具默认返回压缩后的候选清单和材料路径，agent 按需读取相关正文段落；已处理且内容未变的材料复用判断和中文加工结果。

尽量节省 token，但不设置 token 预算、总量上限或扩读限额，也不因 token 使用量暂停处理。分批与摘录仅用于组织材料，必要时继续扩读并完成既定范围内的处理。

token 优化不能以漏掉关键修复、隐去限制条件或把未读取视频当作完整理解为代价。详细流程、缓存失效、按需读取与验证见 [COLLECTION-PIPELINE.md](./COLLECTION-PIPELINE.md)。

## 新增媒体渠道

YouTube、TikTok、X 和微信公众号作为新增来源平台，与官网和项目发布记录一起进入配置。默认跟踪已确认关注对象的官方账号及已核实负责人账号，不因增加平台自动扩大到所有自媒体。

视频先取得标题、简介、发布时间和可访问的字幕／文字稿，再按候选价值处理需要的文本。只有简介、没有字幕或正文时，明确记录材料完整度；可以总结简介中有依据的内容，不能声称已总结完整视频。缺少关键信息时待核查。

RSS 取得的长视频文字稿保留章节和时间戳，按需取相关段落，避免每次向模型送入整段文字稿。首版只使用 RSS 提供的文字证据，缺少字幕或画面依据时保留待核查。

账号需核实身份，平台需记录实际读取能力。原生或转换后的 RSS 订阅按可用性接入，不以付费接口为前提；受限来源明确标记缺口，不能将“取得某一条原文”当作完整账号历史覆盖。具体平台边界见 [SOURCE-REGISTRY.md](./SOURCE-REGISTRY.md)。

## 内容筛选与中文呈现

保留：正式模型发布、显著能力变化、API／价格／使用限制与可用性变化，以及影响开发者工作的 Agent 功能、兼容性变化和关键问题修复。

过滤：普通宣传、重复转发、无实际影响的小调整、传闻和无原始依据的转述。按实际影响判断，不能仅凭版本号大小决定重要性。

负责人明确的一手预告标为“预告”，有价值的个人判断标为“观点”，不能改写成已发生的事实。厂商宣称的性能提升保留原发布者归属，未经独立验证不能写成本站已验证结论。

已核实负责人的 AI 一手动态采用更宽的保留标准，具体见 [采集技能](../skills/ai-news-collect/SKILL.md)：短预告、观点、进展及调查、重置、修复状态通报均可保留；文字短、宣传口吻或缺父帖上下文本身不构成过滤／暂缓理由。按本人表述归属报道，保留实际文字范围，不补造未知背景。身份、日期或原文不可核实时仍待核查，范围外内容、无 AI 信息的纯互动与准确重复仍可过滤。

默认提供中文标题、简短摘要、关键变化和原文链接；短公告可以完整翻译，长文章只总结。摘要保留关键数字、条件和限制，不补写原文没有的结论。

## 事件归并、关联与纠错

- 同一次发布出现在官网、GitHub 和负责人账号时，合并为一张事件卡片，保留多条来源。
- 预告与正式发布分别保留，通过关联关系连接，避免正式发布被旧预告覆盖。
- 不同版本、不同阶段或不同实质变化，不因标题相似而合并。一个事件可以关联多个关注对象。
- 稳定事件标识不随中文标题、摘要和展示名称变化；重复调用不应产生新卡片。
- 原文更正后更新相关内容，保留更正时间与原因。原文暂时不可访问、删除或明确撤回分别处理，不把读取失败当作撤回。

## 采集时间窗与历史

首次采集最近 3 天，实施默认解释为调用时刻回溯 72 小时。后续按来源分别增量更新并补采失败期间的信息，不因下一次调用又只看最近 3 天而漏掉断档。

每个来源分别保存实际成功覆盖的时间范围。失败、访问受限或未覆盖完整时间窗时，不把该区间记为成功；即使成功扫描后没有入选内容，也可以记录该次成功覆盖。

实施时加入少量重叠查询和近期已入选内容复核，用于延迟发布、去重与更正。补采范围无法完整覆盖时，汇报未覆盖区间；不得为未核实内容编造时间。

入选的重要事件长期保留。首页默认展示最近 7 天，支持查询历史；这不改变首次仅回溯 3 天的规则。未入选内容不公开展示，只保留去重和运行核查必需的内部记录。

## 页面功能

公开中文信息流，默认按事件发布时间倒序排列。提供模型／Agent 分类、关注对象、日期筛选和关键词搜索；搜索作用于当前所选日期范围，可切换范围查询历史。

卡片展示中文标题、摘要、关键变化、事件类型、日期、关注对象、来源与原文链接。预告、观点、关联发布和更正有明确标识。

页面展示数据生成时间和来源采集覆盖状态，区分“成功检查但没有重要更新”“部分来源失败”“尚未接入”和“数据较旧”。数据生成时间不等于所有来源都成功采集的时间，也不等于网站发布时刻。

移动端和桌面端均可阅读。首次使用或没有符合筛选条件的信息时提供清晰的空状态，不使用虚构新闻填充。

## 可扩展配置与数据契约

关注对象、信息源和负责人分别配置；使用稳定标识、展示名和别名，一个对象可关联多个来源。新增支持已有格式的对象通常只改配置，不修改页面或 skill 主规则。新增来源格式时再增加必要适配逻辑。

公开 JSON 只包含网站内容、对象元数据、历史索引和经过整理的覆盖状态。补采进度、去重指纹、原始材料缓存与运行记录不进入公开发布目录或公开仓库。

完整字段与一致性规则见 [DATA-CONTRACT.md](./DATA-CONTRACT.md)，采集 skill 的职责、输入和输出见 [SKILL-SPEC.md](./SKILL-SPEC.md)。具体前端工具及辅助脚本在实施时选择，采用能够产出独立静态文件的轻量方案。

## 实施顺序与交付

1. 来源配置与数据契约：登记全部已确认对象，核实各入口，维护负责人明确名单，建立 JSON 校验。
2. 采集脚本与 skill：先建立可复用公共采集模块和平台适配器，再制作调用脚本的 SKILL.md 与必要规则引用；实现首次 3 天、增量、补采、候选输出、缓存复用和结果汇报。
3. 首轮数据：按实际调用时刻采集最近 3 天，形成可追溯的真实内容与覆盖状态；无重要信息时如实输出空结果。
4. 静态网站：完成中文信息流、筛选、搜索、历史读取、事件关联、更正与覆盖提示。
5. 独立发布：配置 GitHub Pages 的免费静态发布流程，验证资源路径和数据版本一致性。

实际交付入口见 README.md。页面与采集实现已完成；来源登记不等于全部订阅已接通，具体覆盖以 public/data/coverage.json 为准。

## 首版验收标准

- 全部 13 个模型及服务平台关注对象、14 个 Agent 对象进入配置；OpenRouter 作为模型服务平台、DeepTutor 作为 Agent 应用登记。每个来源有明确核实与接入状态，负责人采用已核实名单。
- 新增一个使用既有来源格式的对象只需改配置，不需要修改页面或 skill 的核心规则。
- YouTube、TikTok、X、微信公众号来源可以按账号配置登记，统一通过 RSS/Atom 获取；每个入口明确实际可取得的是列表、正文、字幕还是仅元数据。
- 内容未变化的再次调用不重复翻译或摘要，也不重新生成采集脚本；默认工具输出不包含整页 HTML 或整段长字幕。
- 不设置 token 预算或因 token 用量而截断任务；分批读取仍应完成既定范围内的候选处理。因读取失败、材料不足或运行中断而未完成的信息保留待处理状态，不误记为已审阅或没有重要更新。
- 网站只依赖本站静态文件，中文内容可读，来源链接可追溯，模型／Agent、对象、日期筛选和关键词搜索有效。
- 首次只处理最近 3 天；增量调用不重复产生同一事件。某来源失败后恢复，可以补采断档，其他来源的进度不受影响。
- 同一发布多来源合并；预告和正式发布分开关联；关键修复能够入选，普通宣传不会入选。
- 更正有标记，原文读取失败不会被误判为撤回；未知时间、价格或性能结论不靠猜测填充。
- JSON 校验失败不会覆盖上一次有效数据；成功来源的内容可保留，失败区间仍待补采，页面如实显示部分覆盖。
- 长期历史不被新调用删除，默认 7 天视图与首次 3 天采集规则互不混淆。
- 采集调用不直接发布；独立发布后页面和 JSON 属于同一有效快照，GitHub Pages 的项目子路径下仍能正常读取资源。
- 首版不依赖定时任务、常驻后端或额外收费采集 API。
