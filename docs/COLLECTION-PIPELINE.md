# 复用采集脚本与 token 节省

状态：已实现。2026-10-03 根据用户要求统一 RSS/Atom 获取，采集器只读取 RSS/Atom；经用户确认的独立按需转换器负责将官方页面／公开接口转成本地 RSS，详见 [离线 RSS](OFFLINE-RSS.md)。

## 职责划分

| 层 | 负责事项 |
| --- | --- |
| 独立按需转换器 | 官方页面／公开接口转换为私有 RSS 与校验清单，不改变在线覆盖 |
| 公共采集模块 | RSS 条件请求、时间窗口、缓存读写、材料索引和状态保存 |
| 统一订阅读取器 | RSS/Atom、命名空间正文、原始链接、日期和实际文字范围 |
| 确定性处理 | 正文清理、字幕分段、稳定内容标识、指纹、准确重复判定与 JSON 校验 |
| AI agent | 重要性判断、语义事件归并、来源矛盾处理、中英文摘要及必要翻译 |

所有平台通过配置使用同一个 RSS/Atom 读取器；优先原生订阅，转换服务地址集中维护，支持 OPML 导出。不要为每个关注对象复制网络、缓存与状态代码。

## 统一脚本入口与材料契约

提供一套稳定的脚本入口，支持“列出变化”“读取指定材料或段落”“生成待加工候选”“校验并提交数据”等操作。独立函数／模块承担公共逻辑与适配逻辑；具体语言和 CLI 参数在实施时确定。

适配器统一支持：枚举指定账号或入口的变化、读取订阅实际提供的内容、返回实际覆盖区间及读取能力。是否能完整枚举列表、是否取得正文／字幕应分别报告，不以工具退出成功代替内容完整性。

每条材料记录来源标识、平台原始内容标识、规范链接、发布时间及精度、作者／账号、内容类型、内容指纹、正文／字幕本地路径和完整度。视频片段保留时间戳，长文章段落保留可定位的证据位置。

这些是内部工作材料，不直接作为网站事件。最终公开结构仍遵循 DATA-CONTRACT.md。

## 节省 token 的执行流程

1. 脚本读取来源配置与进度，获取时间窗内的变更索引；支持时复用 ETag／Last-Modified、平台内容标识和修改时间。不假设所有平台都支持条件请求。
2. 用确定性规则过滤窗口外、未启用对象和准确重复记录；其他候选保留。关键词可辅助排序，不作为唯一排除条件。
3. 读取订阅提供的正文或字幕，清理 HTML 标签及脚本，在本地暂存。默认工具输出只给简短候选索引、必要摘录与材料路径。
4. 对原文指纹和规则版本都未变的内容，复用既有判断与双语加工结果，包括已经有理由排除的内容。
5. agent 批量检查紧凑候选，按需读取相关正文段落或字幕片段，做重要性与事件判断。不能只凭标题作出涉及具体能力、价格或限制的结论。
6. 优先归并同事件的证据，再在同一事件记录中生成中英文两份摘要；补充来源且事实未变时，不重复重写相同摘要。
7. 脚本做结构化验证与有效快照更新，返回紧凑运行结果。完整 HTML、长字幕、内部日志和全部历史不默认回传给 agent。

同一次调用中相同材料按指纹去重；后续调用中根据原文修改、可用缓存和复核策略决定是否重新获取。来源迁移、解析规则变化、材料完整度改善、筛选规则变化或证据冲突时，对受影响结果重新处理。

## 缓存与保留

分开维护获取缓存、标准化材料缓存和 AI 加工结果缓存。原文已变化时不能仅因链接相同而复用旧摘要；同一 Changelog 页面可包含多个版本，也不能只用整页 URL 作为事件身份。

缓存记录原始内容标识、内容指纹、解析规则版本、筛选／加工规则版本、材料完整度和生成时间。原始订阅 XML 与长文字材料仅作有保留期限的本地临时缓存，不进入公开仓库；长期只保留必要去重、入选依据和修订记录。

内容改动、规则改变或此前未取得的正文／字幕变得可用时，相关缓存失效。即使 metadata 未变，也按复核策略检查近期重要内容，避免只看发布时间而错过原文更正。

## 按需读取与处理完整性

不设置 token 预算、单次 token 上限或必要扩读限额，不因 token 使用量停止任务。根据材料规模分批处理，默认先展示紧凑索引和摘录；涉及关键条件、数字或证据时继续扩读，直至取得足够依据。分批和摘录不限制最终处理的候选总量，也不能把未展示的内容当作不存在。

脚本记录索引条数、材料字符量、缓存命中和避免重复加工的条数。实际 token 用量只有 agent 环境提供可靠计量时才报告，否则只给明确标注的估算或材料规模，不承诺固定节省比例。

完成既定范围内的候选处理。因访问失败、材料不足或运行中断而未完成的候选保留待加工，不把它们标记为不重要。来源“已取回到哪里”和“已审阅到哪里”分别记录；只有相应区间的候选都取得处置结果后，才可称该区间完成内容审阅。

下一次调用优先续处理已取回但未加工的候选，再做必要增量与失败补采；恢复时不要求 agent 重新阅读全部历史或上次完整对话。

## 媒体文本与多模态

视频处理优先使用可取得的标题、简介、作者字幕或平台字幕；保留字幕来源类型，自动字幕可能存在转写误差。长文字稿按章节／时间戳切段，脚本建立索引，agent 按需扩读。

仅有元数据或简介时明确标记材料范围。可以报道简介中明确公布的变化，不能声称已经分析完整视频；缺少支撑关键结论的正文、字幕或画面时待核查。

首版只处理 RSS 提供的文字证据，不额外下载视频、转写或识别画面。图片帖和视频中仅出现在画面的重要信息需要相应证据，不能仅凭标题补写。

## 验证重点

- 多个同平台账号共用一个适配器，新增账号只改配置。
- 内容未变的重复调用不会重复双语加工；确有修改或规则变化时能够重新处理。
- 长正文和字幕不会默认全量进入上下文，重要限制条件仍可通过扩读取得。
- 简介、部分字幕和完整文字稿的完整度状态正确，引用片段可回到原文或视频时间点。
- 不因 token 用量暂停或省略候选；分批处理能完成既定范围，运行中断后可恢复，尚未加工的区间不会被记作全部审阅完成。
- 失败重试和补采不会丢失待加工队列，缓存清理不会删掉网站历史或必要修订依据。
