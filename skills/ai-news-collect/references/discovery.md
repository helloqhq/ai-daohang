# 对象发现与信源维护

每次调用在用户指定范围内完成发现、核实与本地维护。保持“模型厂商 / Agent / 平台 / 名人”四类展示；内容类型、新闻主题和发布平台不是新的对象类别。

## 纳入依据

优先复用已有 RSS、材料、对象别名和计费链接，再查询官网、官方项目、论文及相关产品的官方文档。搜索结果可用于发现，最终以原始依据核实身份、AI 关联和影响力。不要仅凭榜单、营销宣称或账号粉丝数纳入。

- 模型厂商／模型品牌：具有可核实的模型发布、技术贡献或实际采用。
- Agent：应用、运行工具或开发框架直接提供或支持 AI 任务执行；有实际采用、重要生态集成或技术贡献依据。
- 平台：模型接入、AI 推理或相关服务是核心业务，具备可核实的产品和行业影响。通用云服务不因提及 AI 自动入选。
- AI 人物：身份可核实，持续提供 AI 一手研究、产品进展或产业信息，优先负责人、研究者和重要项目作者。人物观点保留归属，不能转述为机构公告。

至少记录一个可核实的实际采用、技术贡献或行业影响理由，以及 AI 强关联依据。没有统一粉丝数或 star 数门槛；规模数字仅在原始依据明确时使用。证据不足者保留候选，不为了填满面板降低标准。

## 去重与登记

先查稳定 ID、官网域名、别名、所属产品与继承关系。改名／迁移通常保留原 ID；一个厂商的新型号、一个套餐的新档位不自动生成新对象或重复订阅。平台分销的模型不记为平台自研。

新增对象写 `config/entities.json`，沿用 `category: model|agent`：

| 对象 | kind |
| --- | --- |
| 厂商、模型品牌、API 平台 | vendor、model_brand、api_platform |
| Agent 应用、运行工具、开发框架 | application、runtime、framework |

新增人物写 `config/sources.json` 的 `people`，来源用 `person_id` 关联。核实人物与账号分别进行；`entity_ids` 是可证实的关联产品／研究对象，不因同名或谈及某公司就虚构任职关系。尚无法建立现有契约所需的相关对象关系时保留候选，不制造占位厂商。

对象与人物提供 `name_en`、别名、身份依据和 `admission`：

```json
{
  "ai_relevance_zh": "具体的 AI 关联",
  "ai_relevance_en": "The specific connection to AI",
  "influence_reason_zh": "有原始依据的采用、贡献或影响",
  "influence_reason_en": "Evidence-backed adoption, contribution or influence",
  "evidence_urls": ["https://官方身份或影响依据"],
  "checked_at": "实际核实的 ISO 日期或时间"
}
```

这段结构是对象的 `admission` 值，不代替对象本身必填字段。字段校验只能证明结构完整，不能证明影响力真实，仍需阅读依据。

## 信源优化

按同一发布者的身份、原始性、日期可靠性、正文完整性和实际可用性选源。通常优先官方原生 RSS / Atom、官方 Releases，再选可核实的转换订阅；不因为原生订阅存在便忽略正文或时间缺失。一个对象可有互补来源，不把 Changelog 当作完整价格信源。

用官网反链或官方项目依据核实账号；第三方 feed 还需抽查原文链接、发布者、日期和正文范围。成功读取一次不证明完整时间窗。新兼容订阅只改配置；需要新离线解析时，复用 `scripts/converters/` 的转换结构并增加真实格式回归检查，通过后才能标为可执行转换入口。不能只写 `offline_conversion: true` 便声称接通。

同一来源更换 feed 时保留 ID，记录原地址、实际检查时间和双语原因（可用来源的 `maintenance` 字段），沿用脚本订阅指纹与断档补采机制。单次超时不自动停用；已核实撤销、迁移或被替代的来源可停用并写明原因，保留旧来源及历史引用。新发布者使用新 ID。不能重置 `.collector/` 或复制旧覆盖来“修复”失败。

候选与未完成尝试存 `.collector/discovery-candidates.json`，使用稳定候选 ID，保留类型、官网／账号、发现依据、待核实问题、尝试日期和处理结果。后续调用复用，证据变化时再核实；公开目录只加入已达到标准的对象，不公开内部候选材料。

维护后运行 `python3 scripts/collect.py feeds`、`python3 scripts/collect.py validate`，执行必要的转换检查和 `refresh` 同步公开目录。新增来源遵循首次回溯窗口，修复来源沿原缺口补采；登记、订阅接通、材料获取、审阅完成分别汇报。
